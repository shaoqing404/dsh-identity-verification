# 会话隐私与加密保护规格（候选）

## 用户任务与当前状态

用户希望暂时遮住会话，离开后让会话重新受到保护，需要时通过系统验证继续使用；还要能在设备损坏或更换时找回自己的数据。界面应明确告诉用户：当前只是遮挡，还是受控副本已经加密并封存。

本规格是下一阶段设计，**尚未实现或验收**。[当前 M3](../validation.md) 只提供身份验证自检：本人成功回执已有记录，系统面板取消、焦点恢复及其他实机项仍待完成。认证成功本身不读取密钥，也不会加密或解封 DSH 会话。日常 DSH 与原有数据不在本阶段操作范围内。

## 三层能力

| 能力 | 用户看到的状态 | 实际边界 |
| --- | --- | --- |
| 隐私展示 | 「已遮挡」 | 会话内容从受支持的界面及无障碍树中隐藏；可选毛玻璃仅作视觉效果。数据是否加密、后台是否仍在运行，单独说明 |
| 静态加密与封存 | 「已加密并封存」 | 对明确列出的受控存储完成加密、落盘校验和关闭读写；已释放可释放的密钥引用。仅覆盖经验证的数据范围 |
| 验证后解封 | 「验证中」「已解封」 | 人为发起，受信调用方对指定会话请求取用受保护密钥；系统认证、密钥访问和解密均成功后才可打开 |

隐私遮挡不阻止其他进程读取已有明文，也不撤回已复制、备份或发给模型的内容。静态加密旨在保护受控密文副本及发现篡改；不声称抵御已授权进程、同用户恶意程序、解封期间的内存读取、屏幕拍摄或已经发生的外发。密钥与明文的内存清理尽力而为，不承诺运行时能保证彻底擦除。

## 状态与交互

1. 用户可手动遮挡；空闲、锁屏、睡眠、切换工作区或退出时自动遮挡/封存是可配置候选，触发项、默认值和时长待确认。启动或恢复时先维持保护状态，再检查是否允许显示内容。
2. 遮挡时隐藏正文、标题、预览、搜索摘要及可复制选择；关闭内容的无障碍暴露，提供清晰的状态、键盘操作和恢复入口。无法可靠隐藏内容的视图显示「此界面不支持隐私遮挡」，不伪称已保护。
3. 毛玻璃用于遮挡层的装饰，不作为唯一遮挡手段。开启系统「降低透明度」、效果不可用或可读性不足时使用不透明遮挡；兼容 VoiceOver、键盘、焦点和高对比度。此前已进入剪贴板或其他应用的内容不自动清除。
4. 请求封存时先停止新的受保护读写，等待已确认的持久化和关闭，校验加密结果，再关闭会话并尽力释放密钥引用。若会话仍在执行、存在未保存内容或无法安全暂停，显示具体状态及用户可选操作；不擅自终止任务，不将单纯遮挡标为封存。处理失败或结果未确认时保留可恢复原件并明确提示。
5. 解封请求绑定会话、用途、调用方、窗口、请求 ID 和有效期；自动封存、窗口关闭或请求取消后，迟到的认证/解密结果不得重新打开会话。解封之后的再次自动封存应重新检查写入、会话运行和密钥状态。

## 加密与恢复候选

优先验证**独立加密容器/后端**：每个会话使用独立随机数据密钥，采用经过审查的认证加密实现（候选 CryptoKit AES-GCM）；每次加密的 nonce 在同一密钥下不可重复。格式版本、会话标识和必要的非敏感上下文可作为附加认证数据，避免密文被换到错误对象；附加认证数据并不自动保密。需设计多段追加、顺序、截断、崩溃和版本升级的检测。完整旧快照的回滚检测还需要另行验证可信锚点，不能仅凭认证加密保证。

密钥保护候选是将解密所需密钥或密钥包装材料交由带访问控制的 macOS Keychain 管理，让密钥读取本身受系统认证约束。独立的 `LocalAuthentication` 成功回执不能替代这个约束。Keychain 的访问组、签名、helper 身份、系统认证策略、复用窗口及失败行为均须在目标版本验证；不能把一次自检成功当作所有操作的长期授权。

恢复与导出必须先于真实数据迁移确定：提供用户主动创建、验证并妥善保存的**独立恢复材料**作为候选；其具体形式、密钥派生方案、离线保管与轮换待设计和安全审查。导出默认应为加密包；明文导出如纳入，须单独明确范围、目的地和用户确认。恢复在隔离环境先演练设备丢失、更换设备、密钥不可用和恢复材料错误；恢复失败保留原加密包。若只使用设备绑定密钥而无有效恢复材料，设备或密钥丢失可能使数据无法恢复，不能称为可迁移。

迁移采用「复制 → 加密 → 完整性和恢复验证 → 用户确认切换」的候选流程；任一步失败保留原件和可恢复副本。旧明文、历史备份和文件系统快照不因新副本加密自动消失；不可承诺安全擦除。针对真实会话的复制、迁移、切换和删除均不属于本计划文档的执行授权。

## 数据范围与 DSH 接口门槛

| 对象 | 必须确认的覆盖或剩余风险 |
| --- | --- |
| 会话事件、标题和列表元数据 | 盘点内容、标题、预览与格式版本；加密范围和允许明文元数据逐项列出，列表不默认暴露敏感标题 |
| 搜索索引与缓存 | 检查索引、摘要、自动补全、Renderer/Host 缓存及临时文件；不能覆盖时列出位置和限制，不能宣传全部会话已加密 |
| 附件、工具输出与工作区文件 | 分清会话内引用与原始文件；逐项验证是否纳入容器。原工作区文件和外部附件默认不因会话加密而改变 |
| 日志、崩溃报告与诊断 | 仅记录去标识化请求状态、错误类别和版本等必要信息；禁止写入正文、密钥、认证凭据和恢复材料。核查第三方日志及崩溃报告 |
| 备份、导出与同步 | 盘点旧明文副本、系统/云备份、快照和用户导出；记录加密包与恢复材料的保管边界，不覆盖既有备份 |
| 模型上下文、后台任务与网络 | 会话历史或附件可能已被发送给模型、工具或远端服务。确认运行任务的暂停/继续、上下文重建和取消机制；已发送数据不能靠本地封存撤回 |

固定上游提交 `66491b0` 的 [会话持久化契约](https://github.com/deepseek-ai/deepseek-harness/blob/66491b0/packages/session/session-persistence/README.md) 允许实现其他后端，并规定追加、单写者、`flush` 与恢复等行为；[会话事件文档](https://github.com/deepseek-ai/deepseek-harness/blob/66491b0/docs/subsystems/session.md) 将 `session/event` 描述为提交后的通知。前者是值得验证的接入面，后者不能单独当作事前拦截或加密门禁。

在目标 DSH 版本的隔离桌面中，仍需证明：第三方后端能否被受支持地装配和停用；能否按会话选择保护；列表/搜索/附件等是否绕过后端；活动会话能否安全暂停、关闭和恢复；界面能否可靠遮挡；是否存在可信调用方与窗口来源、权限撤销及生命周期绑定。现有 exact Fetch owner 不能证明实际调用者或 Desktop 来源，不能用于真实密钥访问。若缺口无法关闭，只交付明确标示范围的独立容器或界面原型，不宣称 DSH 原生存储透明加密。

## 调用方与失败体验

验证器保持通用：不保存会话正文、数据密钥或恢复材料。受保护存储由独立调用方管理，登记调用方与允许的动作，按会话、用途、窗口和期限授予一次性最小权限；拒绝模型、后台 Agent 或未经授权插件直接借用结果。一个受信 Host 中其他原生插件仍可能共享进程能力，不能把接口约束夸大为进程隔离。模型不参与认证和密钥决策。

| 失败路径 | 用户体验与数据状态 |
| --- | --- |
| 来源、权限或保护状态不确定 | 显示「无法确认保护状态」，停止取钥/解封；保留原件，提供检查入口 |
| 超时、失联或进程退出 | 停止等待并撤销该请求；迟到结果作废。若提交结果未知，显示「结果未确认」并先核对状态 |
| 无密钥、无会话、设备不支持或生物识别不可用 | 说明具体可用选项；允许已配置的恢复路径或系统策略后备，不悄悄降级，也不创建空会话覆盖原件 |
| 密文校验失败、格式不兼容或返回异常 | 拒绝打开，保留密文与副本；提供修复/导出线索，不能把损坏数据展示为可信内容 |
| 用户取消、拒绝或认证未通过 | 区分「已取消」和「验证未通过」，结束本次请求，保持原有遮挡/封存状态并恢复焦点；不自动重试、迁移或删除 |

## 验收要求

- M5：在隔离桌面用合成会话核对手动和配置的自动遮挡、无障碍树、键盘和降低透明度回退；对不受支持视图明确报错。证明的只是界面隐私。
- M6：在隔离目录验证加密/解密、错误密钥、篡改、截断、崩溃恢复、备份与异机恢复演练；用合成标记检查已声明存储范围的泄露面。不能将扫描通过说成全系统无明文。
- M7：完成调用方授权、真实系统认证与密钥读取绑定，并以项目维护者亲自操作的结果分别记录成功、取消、焦点恢复和回退；验证关闭、自动封存、失联、竞态及重复消费。M3 尚未完成、DSH 装配、数据覆盖或恢复不成立时，不得标记整合验收完成。
- 每项分别记录源码、隔离测试、安装、实机体验与人工验收状态；仅使用本项目合成会话，按[隔离手册](../native-lab.md)操作，不读取、复制或改动日常环境或真实业务数据。实现和发布另按项目既有流程执行。

## 技术依据（2026-11-17 核对）

- [Apple CryptoKit AES-GCM nonce](https://developer.apple.com/documentation/cryptokit/aes/gcm/nonce) 与 [解密和认证](https://developer.apple.com/documentation/cryptokit/aes/gcm/open%28_%3Ausing%3Aauthenticating%3A%29)：nonce 不可重复；打开密文时验证密文和附加认证数据。
- [Apple Keychain 访问控制](https://developer.apple.com/documentation/security/restricting-keychain-item-accessibility) 与 [使用生物识别访问 Keychain](https://developer.apple.com/documentation/localauthentication/accessing-keychain-items-with-face-id-or-touch-id)：可为密钥项设置访问条件；`userPresence` 允许系统按策略使用生物识别或设备密码，设备绑定选项影响新设备恢复。具体 macOS、签名及发行方式须实测。
- [Apple Secure Enclave](https://developer.apple.com/documentation/security/protecting-keys-with-the-secure-enclave)：支持的密钥类型和导入导出受限；本方案不声称会话的对称密钥天然存储在 Secure Enclave。
- [Apple 视觉效果](https://developer.apple.com/documentation/appkit/nsvisualeffectview) 与 [降低透明度设置](https://developer.apple.com/documentation/appkit/nsworkspace/accessibilitydisplayshouldreducetransparency)：视觉材料和用户系统设置会影响表现，降低透明度时应使用不透明界面。
